## State, data fetching, errors

**State-Haltung — dominantes Muster:** Der gesamte Domänen-State lebt als `useState` in `src/App.tsx` und wird über **Props-Drilling** an die Tabs gereicht. Kein Context, kein Reducer, keine State-Bibliothek (Suche nach `createContext`, `useContext`, `useReducer`, `zustand`, `redux`, `jotai` in `src/`: keine Treffer).
- Jeder State wird **lazy aus `localStorage` initialisiert** (`useState(() => { const saved = localStorage.getItem("morgenroutine_…"); try { return JSON.parse(saved) } catch {…} })`) und mit einem eigenen `useEffect` pro Key zurückgeschrieben: `src/App.tsx:62–86` (`dailyHistory`, `periodLearnings`), `133–385` (`marketState`, `livePrices`, `portfolioData`, `checklistData`, `soldTrades`, `portfolioPurchases`, `customDepots`, `customBesitzer`, `depotStartingCash`, `watchlist`), `430–436`.
- Ein Sammel-Effekt schreibt bei jeder Änderung privater Daten den Zeitstempel `morgenroutine_data_last_modified` (`src/App.tsx:389–393`), den die Backup-Vergleichsansicht liest.
- `PortfolioTab` bekommt neun State/Setter-Paare, `WorkspaceSyncTab` ebenfalls neun plus Callbacks (`src/App.tsx:725–840`).
- „Alles zurücksetzen" löscht alle Keys mit Präfix `morgenroutine_` und setzt die States explizit leer (`src/App.tsx:799–835`).

**Ausnahmen — Tab-lokaler, direkt persistierter State:** `src/components/MorgenroutineTab.tsx:142–205` (`morgenroutine_prices_cache`, `morgenroutine_prices_last_updated`, `morgenroutine_last_live_fetch`), `src/components/PortfolioTab.tsx` (`morgenroutine_atr_length/_multiplier/_smoothing`), `src/components/OnboardingScreen.tsx` und `src/components/PWAInstallPrompt.tsx` (`morgenroutine_onboarding_done`), `src/components/WorkspaceSyncTab.tsx` (alle `g_workspace_*`-Keys, darunter `g_workspace_access_token` und `g_workspace_local_profiles`).

**Backend-Aufrufe — dominantes Muster:** nacktes `fetch("/api/<route>", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(…) })` direkt in der Komponente. Es gibt **kein API-Client-Modul, keinen Wrapper, keine Query-Bibliothek**. Stellen: `src/components/MorgenroutineTab.tsx:267, 272, 501, 1229`, `src/components/RechnerTab.tsx:80, 115`, `src/components/AICoachTab.tsx:79`, `src/components/AuswertungTab.tsx:37`, `src/components/WorkspaceSyncTab.tsx:490, 532`. - **Caching:** kein HTTP-Cache im Frontend; stattdessen wird das Ergebnis des Live-Abrufs als Snapshot in `morgenroutine_prices_cache` abgelegt und kann per „Cache anwenden" erneut eingespielt werden (`MorgenroutineTab.tsx:180–215`); serverseitig ein In-Memory `searchCache` für `/api/stock-search` (`server.ts:1222–1225`) und Rate-Limit-Cooldowns für Gemini (`RATE_LIMIT_COOLDOWN_MS`, `server.ts:785`, genutzt ab Zeile 959 und 1148).
- **Ausnahme:** `src/components/WorkspaceSyncTab.tsx` ruft Google Drive / Sheets / Docs **direkt aus dem Browser** auf (ca. 25 `fetch`-Aufrufe an `googleapis.com`, Zeilen 254–1297) mit einem OAuth-Access-Token aus `localStorage` (`g_workspace_access_token`); der Server ist hier nur für den OAuth-Callback (`server.ts:198`) und den PIN-Profil-Speicher zuständig.
